# Changelog

All notable changes to UpNext are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- Resting the mouse on a pick's art for a second now fades through the game's screenshots inside the art itself, with its top tags along the bottom and dots to pick one, and ends when the mouse moves away. The quick look it replaces opened a panel under the art that covered the card's buttons until it was closed. With reduced motion the pictures change only when a dot is chosen; keyboard users get the same from a "Preview" button that shows on focus, with the arrow keys to step, and a tap on a phone still opens the page.

### Security

- An uploaded GOG Galaxy database is read with SQLite's defensive mode on and its schema untrusted, so a crafted file's views and triggers can't call functions that do more than compute a value.
- A token runs one Settings AI test and one look at the Codex CLI at a time, as it already did picks and Help me decide: each test is a real model call, and each look starts three Codex processes, so a script could run up a bill or pile up processes.

## [0.1.1] - 2026-10-16

### Added

- A Microsoft Store package (MSIX) of the Windows app, which the release workflow builds for the Store, where UpNext isn't listed yet. The Store's copy opens the same library as the installer's, in `%LOCALAPPDATA%\upnext`, keeps it when uninstalled, puts `upnext` in terminals, and starts with Windows once it's turned on in Windows Settings › Apps › Startup.

### Changed

- A new icon, a d-pad with Up pressed, on the app, its window's top bar, the launcher entries, the Windows installer and the Android app.
- The Flatpak is offered as a file on each release rather than on Flathub, where UpNext won't be submitted. [Flatpak and Steam Deck](docs/install/flatpak.md) says how to move an installed copy to a new release, since `flatpak update` doesn't.

### Security

- rustls 0.23.46, for RUSTSEC-2026-0346 to RUSTSEC-2026-0349. UpNext uses neither ECH nor rustls's Brotli certificate compression and never prints TLS session values, so the one that applies is 0349: someone on the network could push UpNext's later HTTPS connections to a server down to classical-only key exchange.

The first public release.

### Changed

- UpNext's shared game data downloads from UpNext's own data server, `https://data.upnext.games/upnext-seed.json`, instead of GitHub's release pages, so new data can be published whenever it's rebuilt rather than only with a release of the app. An address given in Settings › Library data or to `upnext seed apply` works as before.
- Building UpNext from source needs Rust 1.90 or newer (`rust-version` in Cargo.toml, so an older Rust says so plainly) and Node 22.18 or newer; the README asked for current stable Rust and Node 22.12, which the third-party notices script and the web tests had outgrown. The Android app's `core` tests build again without Google's Maven repository (`-Pupnext.coreOnly=true`).
- The backlog verdicts service holds a reported text only on reports from three keys that each have a published verdict of their own. A key costs nothing to make, so three new keys from one address could hold any published text until a moderator looked; reports from keys with no published verdict are still listed for the moderators.
- The backlog verdicts service's moderation page lists every reported text under "Reported texts", not only the held ones, so a text with one or two reports is seen too; "Dismiss the reports" clears a shown text's reports.
- The backlog verdicts service no longer has a limit of 200 verdicts in a key's first week. At 20 new verdicts a day it could never be reached, so the per-key limit is 20 new verdicts a day from the first day, and the service no longer keeps the day a key sent its first verdict.

### Security

- Through a proxy (Tailscale Funnel, Caddy or nginx in front of UpNext), anyone the proxy let in could ask to be allowed, since the request came from the proxy's address, and one careless Allow on the computer would have given them a full token. Asking is judged by who is asking now: through a proxy listed in trusted proxies, the client it names must be on a private network (a tailnet device through `tailscale serve` still may), and through one that isn't listed nobody may ask; such a device pairs with a code. The dialog and `upnext pair requests` say which address asked and through which proxy.
- A copy without keys (Settings' export, a backup downloaded without keys, `upnext export`), which is meant to be safe to share, still held each player's identity provider account (often an email address), the folders a store connection reads (a Heroic folder in your home folder), store accounts' own names, and the household's addresses (`public_url`, the computer's network name, trusted proxies, the identity provider's address, client id, name and allowed groups, your own backlog verdicts service and your own OpenAI-compatible server), and every job's log, result and error and every AI call's error, which can name folders and hosts. They're left out now: a job's log is gone, and a failed job or AI call still reads as failed but says only that its message was left out. Restored on this computer, its own settings come back; the players' identity provider links and the folders on other players' connections don't, so those players link their sign-in and choose their folders again.
- A Steam Web API or RAWG answer that wasn't JSON (an outage page, say) put the request's address, with your API key in it, into the error, which the log and the job's message carry and a read token can see. The key is left out now.
- A download from an `https://` address no longer follows a redirect to plain `http://`: every request UpNext makes refuses that hop, so an answer meant to come over HTTPS (such as the backlog verdicts snapshot, which only the connection authenticates) can't be swapped for one over plain HTTP. Other redirects are followed as before, up to 10.
- A Steam sign-in now works only in the browser that started it, and at most 16 wait at once.
- Behind a proxy on the same computer (`tailscale serve`, Caddy), any token could download a backup with every key in it, or restore, import and delete backups; they now answer only on the computer UpNext runs on, as documented.
- A proxy that rewrites `Host` to `127.0.0.1` (nginx's default) made its visitors "this computer", with no token. A request from this computer that carries a proxy's headers (`X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `Via`…) or speaks HTTP/1.0, as a bare nginx `proxy_pass` does, now needs a token, and the log warns once. A proxy that speaks HTTP/1.1 and strips every forwarding header still can't be told from a local browser.
- From another device, changing the OpenAI-compatible server's address clears its saved key unless a new one comes with it, and that server's error pages are no longer passed back.
- A paired device can no longer read or end a waiting pairing code.
- Restoring or importing a backup keeps the tokens in use, so a revoked token stays revoked.
- API requests another website sends (by `Sec-Fetch-Site` or `Origin`) are refused, GETs included, and the shared data's offer is a `POST` (`POST /api/v1/seed/offer`).
- Every answer forbids framing (`X-Frame-Options`, `frame-ancestors`) and content sniffing.
- The GitHub Actions are pinned to commit SHAs, and the release workflow's build jobs get a read-only token.
- Token and device names leave out control characters, and `upnext token list` prints any older ones escaped, so a paired device's name can't send escape sequences to your terminal.
- From another device, a sync can't name a Galaxy database path of its own, and how many backups are kept can't be changed, since keeping fewer removes the rest.
- A Galaxy upload cut off midway no longer leaves its work file behind, and uploads run one at a time: one that stops sending for a minute is given up, and one kept waiting 30 seconds by another gets a 409.
- Answers from an OpenAI-compatible server are read up to 16 MB, so a small compressed answer can't fill the server's memory.
- Game names, tags and store text go into AI prompts on one line each, retries included, so a name can't add a section of its own to a prompt.
- The container runs with no Linux capabilities and can't gain privileges (`compose.yaml` and the setup wizard's `docker run` line), its base images are pinned by digest, and the compose file shows how to keep the Claude token out of it.
- CI checkouts no longer leave the job's token in `.git/config`.
- A Galaxy upload that sends a little at a time is given up after 15 minutes, so it can't hold the one upload's turn while it drips.
- GOG's "Send to UpNext" bookmark now carries a key of this install's own, so while a GOG sign-in waits, another website can't send your browser to UpNext with a GOG code of its own and link the wrong account; a code without the key is refused, and the log says so without the code. **A bookmark saved before this no longer works: drag Send to UpNext to your bookmarks bar again** from Settings › Accounts or setup. `GET /api/v1/gog/bookmark` gives the key to UpNext's own page, and a copy of the database without keys leaves it out.
