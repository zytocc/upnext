# How the Linux depot works

[The Steam copy](README.md) › How the Linux depot works. Also: [the libraries' source](sources.md).

The libraries come from the system the programs were built on, Ubuntu 22.04 for a release, so the depot is made there: the release job runs on Ubuntu 22.04, and by hand it runs in an `ubuntu:22.04` container (README.md, "Uploading a build by hand", has the command). Each program and library finds the depot's libraries through its own RPATH, which comes before `LD_LIBRARY_PATH`, so the launcher sets no `LD_LIBRARY_PATH` and programs UpNext starts (xdg-open, Claude Code) see the computer's own libraries. They do inherit the launcher's GIO, GSettings, gdk-pixbuf and GStreamer variables. Inside the Steam Linux Runtime that stays in the container, since its xdg-open hands a link to Steam or the desktop's portal, which start the program outside; a copy run without the runtime passes them on, so a GTK program a link starts there would look in the depot's modules first.

What the depot leaves to the computer (`linux-exclude.txt`): glibc, the C++ runtime, the graphics driver and what it loads (X11's and Wayland's client libraries, Mesa's small dependencies), and fontconfig with FreeType, which read the computer's font settings. Steam runs a native Linux title either straight on the computer or in the Steam Linux Runtime 3.0 ("sniper") container, whose pressure-vessel takes glibc, the C++ runtime and the graphics stack from whichever of the computer and the runtime has the newer copy. So the depot needs a computer with glibc 2.35 or newer (Ubuntu 22.04, Debian 12, Fedora 36, SteamOS 3 and later), and `upnext.sh` says so plainly on an older one. It doesn't trim what sniper also has, since the depot's copies come first anyway.

Two things in the depot are changed from the packages they come from, both by `bundle-linux.py`: every program and library's RPATH, and in `libwebkit2gtk-4.1.so.0` the folder it finds its helper processes in. WebKitGTK reads that folder from a path compiled into it, `/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1`, and only a developer build lets a variable move it, so the depot's copy has it rewritten to `././/lib/x86_64-linux-gnu/webkit2gtk-4.1`, the same length and relative to the working directory, and `upnext.sh` starts UpNext in the depot's folder (Steam starts a game in its own folder anyway). Tauri's AppImages do the same.

The launcher doesn't set `XDG_DATA_DIRS` or `GTK_PATH`, so GTK takes its icon theme and any GTK modules from the computer, as every other program there does. The pages draw their own icons, so only GTK's own dialogs (the file chooser) use the theme; a computer with no icon theme shows them without icons.

GStreamer has no plugins in the depot: UpNext's pages play no audio or video, so WebKitGTK never needs one, and `upnext.sh` points GStreamer at the empty `lib/gstreamer-1.0` so the computer's plugins, built for another GStreamer, are never loaded into it.
